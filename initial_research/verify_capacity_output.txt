
==========================================================================
1. PATTERN COUNT vs INFORMATION — the unit error in the root README
==========================================================================
C(10000,100)            = 10^241.8   (count of distinguishable patterns)
log2(C(10000,100))      = 803.3 bits  (payload ONE pattern can carry)

A pattern COUNT is an address space. Its LOG is the storage capacity.
10^241 patterns is not 10^241 bits of knowledge. It is 803 bits.

Upper bound regardless of encoding: an n-unit substrate holds <= n bits.
   n=   10,000 units, w=   100 active:  log2(C(n,w)) =        803 bits  | raw ceiling    10,000 bits
   n=  100,000 units, w= 1,000 active:  log2(C(n,w)) =      8,073 bits  | raw ceiling   100,000 bits
   n=1,000,000 units, w=10,000 active:  log2(C(n,w)) =     80,785 bits  | raw ceiling 1,000,000 bits

The SDR argument shows ADDRESSING is not the bottleneck. True, and never
was in dispute. It says nothing about how many BITS can be stored.

2. KNOWLEDGE CAPACITY OF A FIXED BRAIN (Allen-Zhu & Li: 2 bits/param)
==========================================================================
Weight budget in RAM: 6.5 GB = 52 Gbit
  ^ hard information ceiling: you cannot store more bits than you have.

precision   B/param    params  cap b/p   knowledge  note
fp16           2.00     3.2B      2.0       6.5 Gb  measured
int8           1.00     6.5B      2.0      13.0 Gb  measured - no loss vs fp16
int4           0.50    13.0B      0.7       9.1 Gb  MEASURED COLLAPSE, not a storage cap
ternary        0.20    32.5B      0.7      22.8 Gb  EXTRAPOLATED from int4; unmeasured, trend is downward

BEST MEASURED CONFIGURATION : int8 at 13.0 Gbit
Largest number in the table : ternary at 22.8 Gbit  -- but that row is EXTRAPOLATED, so it is not a result.
Planning uses the MEASURED figure. Ternary's apparent advantage rests
entirely on an unmeasured assumption, and the measured trend is downward.
KEY CONSEQUENCE: int4 holds 2x the PARAMETERS of int8 but LESS KNOWLEDGE
  (9.1 Gbit vs 13.0 Gbit). Quantizing below int8 is counterproductive for
  knowledge capacity. Ternary is worse still. Run capacity experiments at int8.

EXPOSURE REQUIREMENT (the other thing that was missed):
  2.0 bits/param requires each fact seen ~1000 times during training.
  At ~100 exposures an undertrained model reaches only 1.0 bits/param.
  => a 1-epoch training run CANNOT reach the baseline, and P1 would fail
     its gate for reasons unrelated to architecture.

==========================================================================
3. IS THAT ENOUGH? — what the ceiling actually buys
==========================================================================
Raw storage ceiling in 6.5 GB :   52.0 Gbit (unreachable)
Best ACHIEVABLE (int8, measured)   :   13.0 Gbit

  English Wikipedia + textbooks           14.0 Gb   SHORT by 1.1x
      Allen-Zhu's own estimate for a 7B model
  30B-token web corpus (long tail)       240.0 Gb   SHORT by 18.5x
      ~4 chars/token, ~2 bits/char compressed
  300B-token corpus (the Pile)          2400.0 Gb   SHORT by 184.6x

=> CORRECTED CONCLUSION (supersedes the '3.7x headroom' claim):
   A fixed brain in 6.5 GB reaches 13.0 Gbit at int8, versus
   ~14 Gbit for Wikipedia+textbooks: 0.93x. That is PARITY, NOT HEADROOM.
   The earlier 3.7x figure assumed 2.0 bits/param at ternary; the measured
   int4 collapse to 0.7 says that assumption was wrong and optimistic.

   The architecture decision still stands -- RAM is 28x faster than SSD and
   is still the right tier for the load-bearing knowledge -- but the margin
   is gone. The conditional overflow tier is now LIKELY to be needed, not
   merely possible, and Phase 2 must measure where the boundary actually is.

==========================================================================
4. WHERE THE KNOWLEDGE SHOULD LIVE — bandwidth comparison
==========================================================================
tier                             bandwidth         holds   relative speed
fixed brain (RAM)                    84 GB/s         13 Gb             28x
external bank (SSD)                   3 GB/s      ~1600 Gb              1x

The earlier design put 97% of parameters on the tier that is 28x slower.
Dynamics-first puts the load-bearing knowledge on the 28x faster tier and
uses SSD only for what genuinely exceeds the information ceiling.

==========================================================================
5. THE EXPERIMENT THAT DECIDES IT — knowledge bits per parameter
==========================================================================
Allen-Zhu baseline for a standard dense transformer : 2.0 bits/param
Question nobody has published an answer to:
  does a dynamic/Hebbian substrate (BDH/TTT-style) beat 2.0 bits/param?

  measured b/param                                       verdict
             0.5      KILL: dynamics is worse than plain weights
             1.0  KILL for knowledge; keep dynamics for reasoning only
             2.0        parity - premise not proven, not refuted
             3.0                     PREMISE PROVEN, publishable
             4.0                     PREMISE PROVEN, publishable

Capacity a fixed 6.5 GB brain would hold at each rate (int8, 6.5B params):
   1.0 b/param ->   6.5 Gbit = 0.46x Wikipedia+textbooks
   2.0 b/param ->  13.0 Gbit = 0.93x Wikipedia+textbooks
   4.0 b/param ->  26.0 Gbit = 1.86x Wikipedia+textbooks

   Beating 2.0 b/param is not a vanity target: at int8 the fixed brain is
   at 0.93x Wikipedia+textbooks. The premise has to WIN for the
   dynamics-first architecture to stand without an overflow tier.
